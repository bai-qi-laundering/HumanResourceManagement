# 徵人儲存修正（2026-10-30）

已修正可重現的問題：同一瀏覽器多開人資分頁時，另一頁讀取資料會更換共用 Cookie 的驗證碼，讓原頁尚未送出的表單被拒絕。現在讀取資料沿用有效驗證碼；來源網路、Host、Origin 及 CSRF 檢查仍保留。

其他調整：

- 儲存應徵者、電話或面試紀錄後直接開啟該應徵者歷程，避免被名單篩選條件藏住。
- 必填或日期格式不正確時，在表單顯示尚未儲存及需要檢查的欄位。
- 後端拒絕時保留原表單內容及錯誤訊息。
- 寫入成功但重新讀取失敗時，明確說明已儲存，避免重複新增。

沿用 `scripts/update-nas.sh` 更新，執行前會備份 SQLite 及舊程式；保留原本 `.env`、資料庫與文件。

更新後，先將尚未儲存的文字複製到安全位置，再關閉所有舊人資分頁，重新開啟公司內網網址。測試新增一位應徵者，確認看到「資料已儲存於NAS」，重新整理後資料仍在。再新增電話紀錄，確認完整歷程中看得到內容。

此修正已通過後端持久化、多分頁驗證碼、錯誤驗證碼拒絕及前端提交測試；仍須在實際 NAS 確認。若問題繼續，請提供按儲存後的完整畫面與紅字，並指出是新增應徵者、編輯應徵者、電話紀錄或面試紀錄。
