# Synology NAS 安裝：人資限定公司使用

這份程式已寫好，但不知道你 NAS 的實際 IP、網段和資料夾位置。以下必須用真實值替換；不是複製範例就能直接接上文件。

## 1. 上傳專案

在 GitHub 專案按 **Code → Download ZIP**，解壓縮。用 File Station 將內容上傳到一個獨立專案資料夾，例如 `/volume1/docker/HumanResourceManagement`。

同層應看到 `Dockerfile`、`compose.yaml`、`server.py`、`public/`、`.env.example`。不要只下載一個 HTML 放 Web Station。

## 2. 查實際設定

- **NAS 內網 IP**：DSM → 控制台 → 網路 → 網路介面。使用固定的 `192.168.x.x` 或公司实际內網地址，勿填 QuickConnect/Tailscale 地址。
- **辦公室網段**：由公司電腦 IP／子網路遮罩確認，例 `192.168.1.0/24`。若員工、訪客 Wi-Fi 共用網段，先分隔授權辦公室網段；程式沒有個人權限可代替網路隔離。
- **原資料夾路徑**：File Station 找到三個資料夾，查看內容／位置，確認位於 volume1 或 volume2；檔案保留人名，不需改。
- **共同帳號 UID/GID**：DSM 排程器建立一次性的「使用者自訂指令碼」，以管理員執行 `id '你的共同帳號名稱'`，從輸出取得 `uid=數字` 和 `gid=數字`。不需要提供密碼給網站。不要猜 1026。

## 3. 準備 `.env` 和資料庫資料夾

把 `.env.example` 複製成 `.env`，用文字編輯器填入實際值。包含中文／空白路徑時直接填完整文字，勿改原文件名稱。

預先建立 `HR_DATA_PATH` 指定的資料夾，例如 `/volume1/docker/baiqi-hr/data`。File Station 設定共同帳號可讀寫此資料夾，以及可讀原證件資料夾。

程式容器使用這個數字 UID/GID。三個原文件資料夾使用唯讀掛載；即使 App 被誤操作，也沒有原檔刪除介面。`create_host_path: false` 會在路徑打錯時停止建立，避免掛到空資料夾卻誤以為文件消失。

`HR_GAS_URL`、`HR_GAS_SECRET` 可先空白，部署介面及文件功能不受影響。

## 4. Container Manager 啟動

1. Container Manager → **專案 → 建立**。
2. 名稱 `baiqi-hr`，路徑選剛上傳的專案資料夾。
3. 使用該資料夾中的 `compose.yaml` 建立並啟動。
4. 第一次會下載 Python 容器並安裝 Gunicorn，需要 NAS 有外連網路。
5. 完成後，容器 `baiqi-hr` 應在執行。
6. 公司電腦／iPad 開 `http://NAS實際內網IP:8090`。

如不能啟動，先看容器記錄：錯誤通常是 IP 未屬於 NAS、資料夾不存在、UID 沒寫入權限或網段填錯。不要改成 root 或開放所有網段處理。

更新程式後在原專案重新建置（包含 build）並啟動；不刪 `data`，網址和資料都保留。單純 restart 不會載入新的程式碼。

## 5. 文件配對

1. 新增員工，或按打卡同步／JSON 匯入。
2. 連線與匯入 → 檢查三個資料夾顯示「可讀取」。
3. 按「掃描文件」，到「文件配對」確認。
4. 單一相同姓名會提出建議；重名會列多位人員，不能自動選擇。
5. 選對員工，按儲存，再從員工檔案 → 證件文件 → 開啟存摺。

支援 JPG、JPEG、PNG、WEBP、PDF；HEIC、Word、SVG 等不直接預覽，請先轉成支援格式。文件以檔名匹配，範例 `王小明.pdf`、`王小明_正面.jpg`。

## 6. 內網與 Tailscale 限制（部署時必做）

程式碼有多層限制，但**不能只靠程式推断穿過路由器的真正來源**：

- Docker 只把 8090 發布在指定 NAS LAN IP，不綁定所有介面。
- API 只允許 `OFFICE_CIDRS`；Tailscale 的 100.x、公網、其他公司網段不允許。
- 不信任 `X-Forwarded-For` 等轉送標頭，拒絕反向代理請求。
- 不接受 NAS 自己的 LAN IP 轉送，以降低 NAS VPN／代理 masquerade 繞過的風險。
- 禁止路由器將 8090 轉發到外網；不要建立 QuickConnect 公開連結、Web Station 或 DSM反向代理規則，不執行 `tailscale serve/funnel`。
- NAS 防火牆只允許**指定辦公室來源網段／介面**存取 TCP 8090，其餘拒絕。Docker 可能有獨立封包規則，務必實際驗證，不只看防火牆勾選狀態。
- 若有 Tailscale subnet router，遠端來源可能經另一台路由器偽裝為 LAN IP，程式無法單獨辨識。要在 Tailscale ACL/grants 或路由器阻擋「所有人資服務 LAN IP 的 TCP 8090」，並檢查代理是否轉送且移除標頭。**不要加入VPN／Docker來源網段當作修復方式。**

上線驗收：

1. 指定公司電腦可開啟人資和文件。
2. 手機改用行動網路不能開。
3. 手機／家中電腦開著原Tailscale，使用同一內網IP:8090也不能開。
4. 公司訪客或未授權員工網路不能開。
5. 回公司可再次開啟，網路中斷時頁面會隱藏已載入內容（每15秒檢查）。

HTTP 初次測試僅適用隔離的可信辦公室網路；正式處理證件建議啟用內網 HTTPS。可將 TLS 憑證直接交给 Gunicorn，保留真實來源 IP 限制；不要未經調整就用公網代理或開放全公司網段。已截圖／另存的文件無法遠端收回。

原設備系統、AI系統及 DSM 可維持原有連線；只限制人資的8090，不需要移除整個Tailscale。

## 7. 初版使用範圍

這是一套共同帳號的內部管理介面；網段內具有存取權的人都能編輯。沒有員工端外部登入、個人角色或 LINE 員工自助頁，避免違反「回家不能開」。若後續需要主管／財務分權，應先加入獨立登入，不要把 NAS 共用資料夾權限誤當成網頁已有個人授權。
