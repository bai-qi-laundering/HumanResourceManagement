# 特休來源及各組徵人需求

## 特休Excel

在「特休紀錄 → 匯入特休Excel」選擇未加密的 .xls / .xlsx（上限20MB），先預覽再確認。
可讀取姓名／員工、到職日／入職日、天數、已休、結算日期及原始備註。
民國日期會轉換為西元；7+3等純數字加法可辨識，空白不推定為0。
所有原分頁保留，可用下拉選單切換；如有純年度115、114等，預設最新年度。

姓名唯一時配對既有員工；同名或未建檔者保留為待配對，可逐筆「配對員工」。
預覽會提示各分頁到職日不一致、與員工檔案不一致、結算標題與儲存格年份不符等。
重複來源內容略過；同一列內容變更後再次匯入保留為另一份歷史快照，不覆蓋舊版。
原資料含已結清、舊年度及待核對文字，因此不將其自動加成可休餘額，也不覆蓋員工到職日。
人工時數帳本仍以核給、已休、調整、結清記錄正確期間；Excel快照不計入該帳本。
這版尚未導入依到職日自動核給，需另確認公司的特休年度制度、已休及結清資料。

## 徵人目標

1. 先同步員工名單，確認部門、到職日、離職日。
2. 在徵人頁「新增部門需求」選擇員工檔案中的部門，填要補足的人數及原因。
3. 系統保留建立當時該部門在職人數作為基準。
4. 實際報到請用「報到並轉為員工」，選實際部門及到職日；只有應徵者狀態改成已報到不計入。
5. 員工離職請在員工檔案登記離職日，或從原打卡試算表同步異動。
6. 隨時可在該組按「增加需求」，原基準及異動歷史保留。

計算：淨補足＝目前該部門在職數－建立需求時在職數；完成度＝淨補足／累計需求，顯示範圍0～100%。
例如基準20人、需補5人，現在22人顯示2/5及40%；其中1人離職後顯示1/5及20%。
若現在19人，淨補足-1、進度0%，還需6人。若人數超過目標，完成度顯示100%，仍保留實際淨補足數。

離職日當天仍列在職，隔日扣除；未到到職日者不列在職。缺到職日且未離職的既有員工沿用在職判定。
部門調動、補正或同步名單也會改變目前在職數，因此本功能衡量淨人力，並非只統計應徵者錄取率。
需求從建立後追蹤，不將歷史所有報到人員當作本次完成數。

在人資儲存異動後立即重算；徵人頁開啟且未編輯表單／欄位時約每分鐘重新讀取NAS狀態。
更新進度只讀NAS；原打卡試算表的異動必須按「同步打卡員工異動」才能納入，不會背景自動呼叫GAS。
多台電腦同時增加同一組需求時，過期版本拒絕寫入，避免互相覆蓋。

資料與配對皆保存在NAS的hr.sqlite3；GitHub只有程式碼，沒有實際員工或Excel內容。
