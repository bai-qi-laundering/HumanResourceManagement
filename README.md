# 百麒人資管理

公司內網使用的人資系統，部署在 Synology Container Manager。GitHub **只存程式碼**；員工資料庫、薪資與證件留在 NAS。不要以 GitHub Pages 部署這套系統。

## 已完成的第一版

- 員工檔案：新增／編輯姓名、部門、職務、到離職日、緊急聯絡人、纸本原件位置；以員工編號連結。
- 勞保／健保／勞退：分別記錄實際生效日、異動、級距及確認狀態。
- 證件：掃描原「身分證／存摺／駕照」資料夾，依人名提出配對；管理員確認後在員工頁直接預覽圖片／PDF。
- 特休：以時數、期間及核給／已休／調整／結清記錄管理餘額，不和月休混用。
- 特休Excel：預覽後匯入各年度來源、到職日、天數及結清備註，標示衝突及待配對；歷史資料不自動核給成目前餘額。
- 各組徵人目標：隨時增加需求，以建立需求時的在職人數為基準，隨實際報到及離職更新淨補足進度。[操作說明](docs/LEAVE-AND-HIRING.md)
- 薪資：人工登錄或匯入原系統已計算的薪資，保留歷史版本、核定及付款狀態；不重新推算工資。
- 打卡連動：提供 HMAC 驗證的 Apps Script 只讀匯出器；同步員工、最近兩個月的原始打卡及薪資計算明細。
- NAS SQLite 持久化、樂觀鎖避免兩台電腦覆蓋更新、共同帳號操作日誌。
- 公司 IP 網段／Host／來源網頁檢查，拒絕 Tailscale IP、代理轉送；文件無公開連結、不快取。離線檢查會隱藏已載入頁面資料。

尚未接上你的 NAS 或試算表；部署後才會有真實資料。首版沒有範例員工混在實際資料庫內。

## 安裝

詳細圖文步驟：[NAS 安裝與內網限制](docs/NAS-SETUP.md)。

1. 下載此專案 ZIP，解壓後上傳至 NAS 的 `/volume1/docker/HumanResourceManagement`（依你實際 volume 調整）。
2. `.env.example` 複製成 `.env`，填 NAS 固定內網 IP、辦公室網段、共同帳號 UID/GID、資料庫資料夾及三個既有文件資料夾。
3. 預先建立資料庫資料夾，給共同帳號可讀寫；證件資料夾只需可讀。
4. Container Manager → 專案 → 建立 → 選上傳的專案路徑 → 使用 `compose.yaml` → 建置並啟動。
5. 在公司開啟 `http://你的NAS內網IP:8090`。**這不是 GitHub 網址，也不是 DSM/QuickConnect/Tailscale 網址。**
6. 在「連線與匯入」確認文件資料夾可讀；新增或匯入員工後，掃描並確認文件配對。
7. 依部署文件設定 NAS 防火牆及 VPN 限制，並用公司／回家網路實際驗證。

需要填的值都留在 NAS 的 `.env`，不要提交 GitHub。範例 IP/路徑不是你的真實設定。

## 沿用目前打卡系統

先部署人資，文件功能不依賴打卡串接。要同步時依 [打卡串接說明](docs/ATTENDANCE-INTEGRATION.md) 操作。

**不是整份覆蓋現有 Code.gs**。只新增 `integration/HrExport.gs`，在原 `doPost` 的 JSON 分流處加入一行，再設定雙方共用密鑰並更新原部署。Webhook、LIFF 網址不換。

同步只讀取已存入試算表的薪資，不重算、不推送訊息。不包含尚未結算或被缺卡排除的薪資；每月結算後匯入一次，才會建立 NAS 歷史。原試算表已被覆蓋的舊月份不能憑空還原。

## 資料與功能邊界

- G 欄狀態空白的打卡仍會匯入；HR 不改動既有薪資的配對與 22 小時規則。
- HR 保險、特休帳本目前不回寫原薪資公式。請假核准與自動計薪扣款是下一階段，避免這版擅自改現有規則。
- 特休目前人工核給、按期間記錄；未自動計算法定額度、駕照效期，也未自動寄通知。
- 紙本放公司人事櫃，系統記錄存放位置及掃描影本。
- 員工檔案 → 證件文件可選檔或拍照上傳至原 NAS 資料夾，單份上限 12MB。上傳自動綁定員工，以編號、姓名、文件類型、時間及隨機碼命名；每次建立新檔，不覆蓋舊檔。支援 JPG、PNG、WEBP、PDF。
- 新增「徵人」分頁：應徵者資料、每日電話及面試紀錄、下次追蹤、面試預約、進度及報到轉員工。轉入只新增 NAS 人資資料，不回寫打卡試算表或 LINE 綁定。
- NAS 更新與寫入權限請看 [文件上傳及徵人更新](docs/UPLOAD-RECRUITMENT.md)。
- 文件配對只靠檔名建議，**不做證件 OCR、不自動確認身分**。同名員工須手動選擇。
- 共用使用模式沒有個人帳號／分角色審核，只記錄來源 IP 和時間；公司指定網段內能開此人資服務者有相同操作權限，務必只允許辦公室授權網段。
- 刪除功能暫不提供；人事／保險異動以新增更正紀錄保留軌跡。

## 本機開發及驗證

API 與資料庫使用 Python 3.12 標準函式庫；容器使用 Gunicorn 提供 HTTP。單元測試不需要安裝其他依賴：

```sh
python3 -m unittest discover -s tests -v
node --check public/app.js
```

本機介面測試（僅限本機，非正式 NAS 服務）：

```sh
python3 server.py
```

開啟 `http://127.0.0.1:8090`。此模式不讀真實 NAS 文件；可用 `HR_IDENTITY_DIR` 等環境變數指定测试資料夾。

## 備份

備份 `/data` 對應的整個 NAS 資料庫資料夾，以及原三個證件資料夾。SQLite 使用 WAL，備份時請先停止 `baiqi-hr` 容器再做檔案備份，或使用 SQLite backup API；不要只複製運行中的 `hr.sqlite3` 而忽略 WAL。

NAS 不是備份本身。建議加密的異地版本備份，定期測試還原。原有設備與 AI 系統不需停止或改設定。

## 徵人Excel匯入

徵人頁可直接選擇Excel（.xlsx／.xls）或徵人整理檔，依日期範圍預覽後匯入。同姓名電話合併、保留各次歷程、重複來源略過；跨多日且日期不明的原分頁保留範圍，不推定聯絡日期。詳見 [匯入說明](docs/RECRUITMENT-EXCEL.md)。
